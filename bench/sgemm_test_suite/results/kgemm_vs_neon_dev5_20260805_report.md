# dev-5.0.0 KGemm vs 原生 NEON 性能验证

## 测试对象与配置

- dev-5.0.0 提交：`b94898b65 Add KGemm TensorContraction backend`。
- 测试计划：`sgemm_test_plan.csv`，84 个 `(m,k,n)`，SHA-256 为 `14907eb...3c92e`。
- 验证机：Kunpeng 950 7592C，最高 2.3 GHz，固定 CPU 100。
- 编译器：Clang 17.0.6，`-O3 -DNDEBUG -flto -march=armv9-a+nosve`。
- Tensor 配置：`DefaultDevice`、单线程、RowMajor、`C=A*B`。
- 每个尺寸 7 个样本，每个样本至少 250 ms，使用中位 GFLOP/s。
- KGemm 二进制额外定义 `EIGEN_NEON_USE_KGEMM=1`；原生二进制不定义该宏。

## dev-5.0.0 全量 84 个尺寸

| 指标 | 结果 |
|---|---:|
| KGemm 胜出 | 78 / 84 |
| 原生胜出 | 6 / 84 |
| KGemm 至少快 5% | 70 / 84 |
| KGemm 至少快 10% | 60 / 84 |
| KGemm 至少快 20% | 41 / 84 |
| 几何平均加速比 | 1.303x（+30.3%） |
| 中位加速比 | 1.199x（+19.9%） |
| 所有尺寸各执行一次的聚合加速比 | 0.998x（基本持平） |
| 排除 4096³ 后的聚合加速比 | 1.000x |
| 最大维度不超过 1536 的聚合加速比 | 1.016x |

## 按计划顺序前 44 个尺寸

| 指标 | 结果 |
|---|---:|
| KGemm 胜出 | 42 / 44 |
| 原生胜出 | 2 / 44 |
| KGemm 至少快 5% | 41 / 44 |
| KGemm 至少快 10% | 39 / 44 |
| KGemm 至少快 20% | 30 / 44 |
| 几何平均加速比 | 1.494x（+49.4%） |
| 中位加速比 | 1.363x（+36.3%） |

前 44 个尺寸仅 `(1,16,16)` 和 `(1,24,16)` 退化，首轮分别为 `-19.9%` 和 `-22.7%`。

## 退化和反序复测

| `(m,k,n)` | 首轮变化 | 反序复测变化 | 结论 |
|---|---:|---:|---|
| `(1,1,1)` | -63.1% | -62.4% | 稳定退化 |
| `(1,24,16)` | -22.7% | -23.0% | 稳定退化 |
| `(1,16,16)` | -19.9% | -16.5% | 稳定退化 |
| `(3,3,3)` | -10.6% | -9.9% | 稳定退化 |
| `(2048,2048,2048)` | -1.1% | -1.3% | 稳定小幅退化 |
| `(4096,4096,4096)` | -0.3% | +0.3% | 测量噪声范围内持平 |

RowMajor 将外部 `(m,k,n)` 映射为内部 `(n,k,m)`，因此外部 `m=1` 会命中 Eigen 原生 GEMV。当前 KGemm 尝试在 GEMV 判断之前执行，三个 `m=1` 退化尺寸使用了完整 KGemm；让原生 GEMV 优先可规避这部分退化。

## 与 dev-3.4.0 对比

| kernel / 范围 | dev-5 相对 dev-3.4 几何平均 | 中位比 | 聚合比 |
|---|---:|---:|---:|
| KGemm / 全量 84 | 0.999x | 0.999x | 0.999x |
| KGemm / 前 44 | 0.998x | 0.999x | 0.997x |
| 原生 NEON / 全量 84 | 1.006x | 1.032x | 0.962x |
| 原生 NEON / 前 44 | 1.004x | 1.041x | 1.034x |

KGemm 跨分支性能基本不变，说明移植没有引入可观测热路径退化。KGemm 相对原生的加速比分布变化主要来自 Eigen 5.0 原生路径：部分窄矩阵变慢，而大尺寸聚合吞吐也有变化。

两套结果的 checksum 因 FP32 归约顺序存在低位差异，最大相对差异约 `2.0e-5`；dev-5.0.0 独立正确性验证为串行 144/144、ThreadPool 回退 76/76，表达式、double 和双布局检查全部通过。
